# Архитектура и правила работы

## Назначение и стек

KSENIA — портфолио графического дизайнера, полностью статический клиентский сайт.
Bun 1.4.2, TypeScript 7, SolidJS 2.0.0-rc.7 и Vite 8.
Solid закреплён на конкретной RC-версии; это не финальный стабильный релиз.
Python, серверные обработчики, API и база данных отсутствуют.
Bun нужен только разработчику и GitHub Actions. GitHub Pages раздаёт HTML/CSS/JS и ресурсы.

## Работа приложения

1. Браузер открывает HTML и загружает собранный JS/CSS.
2. App определяет маршрут с учётом BASE_URL и показывает нужный TSX-компонент.
3. Внутренние ссылки обновляют History API и состояние Solid без перезагрузки страницы.
   Внешние ссылки, модифицированные клики и скачивания работают стандартно.
4. Карточки вызывают openGallery, openLogo или openReader.
5. Viewers открывает native dialog. Escape, кнопка и фон закрывают его;
   фокус возвращается на исходную кнопку.
6. Галерея удерживает прежнюю картинку до декодирования следующей. Кеш хранит до 16
   изображений; соседние кадры готовятся после текущего. Номер запроса предотвращает
   показ устаревшего кадра после быстрых переключений или закрытия.

TSX рендерится JavaScript в браузере. Входные HTML для внутренних адресов позволяют
открывать и обновлять страницы на статическом хостинге без rewrite. SSR-runtime нет.

## Маршруты

- `/`: главная; якоря #work, #other-things, #about, #contact.
- `/work/logofolio/`, `/work/packaging/`, `/work/marketplace/`, `/work/layout/`, `/work/experiments/`.
- `/projects/expresso/`, `/projects/riviera/`, `/projects/fashion-lab/`.
- `/404.html` и неизвестные пути: страница ошибки.

При добавлении страницы обновить App и генерацию статических входных файлов.
Использовать url() для локальных ссылок и asset() для медиа. Не добавлять жёсткие
корневые пути в TSX: project Pages работает под /REPO/. CSS-адреса обрабатывает Vite.

## Команды

```sh
bun install --frozen-lockfile
bun run dev
bun run typecheck
bun run build
bun run preview
```

Dev: http://127.0.0.1:5173. Preview: http://127.0.0.1:4173. Не открывать HTML через file://.
Для проверки версии с префиксом Pages в PowerShell:

```powershell
$env:BASE_PATH='/ksenia-portfolio'
bun run build
bun run test
```

Тесты рассчитаны на этот префикс. На Windows используют установленный Microsoft Edge,
на Linux — Chromium (`bun x playwright install --with-deps chromium`). BASE_PATH задаётся
перед сборкой; для локального корневого просмотра переменная должна быть пустой.

## Публикация

Workflow при push в main или ручном запуске устанавливает Bun, выполняет
bun install --frozen-lockfile, получает базовый путь через configure-pages,
собирает фронтенд и публикует только dist через upload-pages-artifact/deploy-pages.
В настройках Pages используется GitHub Actions. PAT и секреты в проекте не нужны.

## Правила изменений

- Исходные ресурсы теперь в public/assets. Не удалять их вместе с dist.
  После миграции dist можно пересоздавать: Vite копирует public автоматически.
- Сохранять SVG и JPG побайтно. WebP и миниатюры — отдельные варианты доставки.
  .gitattributes отключает преобразование строк в SVG.
- Сохранять лицензии и источники; временные макеты не выдавать за реальные кейсы.
- Контакты менять в src/data/content.json; тексты главной и части коллекций находятся в TSX.
- В карусели три проекта и четыре заглушки. Заглушки маркетплейсов не открываются.
- Solid 2 использует createEffect(compute, effect) и DOM-импорты из @solidjs/web.
  Не копировать несовместимые примеры Solid 1 без проверки типов.
- Порядок CSS в main.tsx: site, home, revision, header, logofolio, marketplace, app.
  Перед удалением старых правил проверять каскад и затронутые страницы.
- Не возвращать глобальный MutationObserver для типографики и ручную перерисовку всего DOM.
- Сохранять клавиатуру, фокус, жесты, alt-тексты и prefers-reduced-motion.
- После изменений запускать typecheck и build; для интерактива — соответствующие тесты.
  Визуальные правки проверять на 390, 768 и широком экране.
- README намеренно удалён по просьбе владельца; архитектура и команды находятся здесь.
- references/v11-final-verification.md относится к архивной версии на Python.
  Текущие проверки описаны в tests/site.spec.ts.
